# 离线文件数据处理器

一个功能完整的离线文件数据处理桌面应用，支持 CSV/Excel 文件的数据匹配与补充。

## How to Run

```bash
# 进入前端目录
cd frontend

# 安装依赖
npm install

# 开发模式启动
npm run electron-dev

# 运行单元测试
npm test

# 构建生产版本
npm run build

# 打包桌面应用
npm run dist          # 当前平台
npm run dist:win      # Windows
npm run dist:mac      # macOS
npm run dist:linux    # Linux
```

## 测试数据

本应用为纯离线版本，无需登录账号，所有功能开箱即用。

测试数据位于 `sample_data/` 目录：
- `file_A_source.csv` - 源数据文件
- `file_B_target.csv` - 目标文件

## 题目内容

开发一个功能完整的离线文件数据处理桌面应用，该应用需包含用户友好的前端界面和高效可靠的本地后端处理功能，具体需求如下：

### 1. 文件上传功能
- 实现支持用户上传至少两个数据文件（文件A和文件B）的界面组件，包含清晰的文件区分标识
- 支持常见表格文件格式，包括但不限于CSV（逗号分隔值）、Excel（.xlsx、.xls）等格式，需明确列出支持的完整格式列表
- 提供严格的文件类型验证机制，仅允许上传指定格式的文件，并显示明确的不支持格式提示
- 实时显示上传进度百分比和状态指示（准备中、上传中、上传完成、上传失败），失败时提供具体原因

### 2. 数据匹配与补充功能
- 实现从文件A中提取用户指定数据特征（列）的数据值的机制，支持多列同时选择
- 开发高效的数据匹配算法，基于用户指定的主键列将文件A中的数据值准确匹配并补充到文件B中对应的相同数据特征（列）
- 对于文件B中存在但文件A中不存在的数据特征，统一使用空值（NULL或NaN）进行补充，并在预览时明确标识
- 提供直观的数据特征选择界面，以列表或可视化方式展示文件A和文件B的所有列，允许用户通过勾选或拖拽方式指定需要从文件A提取的列

### 3. 结果生成功能
- 自动生成一个新的补充完成的表格文件，文件名建议包含原始文件名和处理日期时间戳
- 支持将结果文件保存为多种格式（至少包括CSV和Excel），并提供格式选择选项
- 提供结果文件下载功能，允许用户选择保存路径，并显示下载完成提示和文件位置指引

### 4. 排序与结构要求
- 确保新生成表格的数据样本顺序严格按照文件B的原始数据样本顺序排列，不得更改
- 保持文件B的原始数据结构不变，包括列顺序、数据类型、格式设置等所有属性
- 保存为 Excel 格式时采用原位写入策略：仅更新/新增 cell.v，保留原有 cell.t / cell.z / 样式属性，不重建表格结构
- 非目标特征数据必须保持原样，不得有任何修改、删除或格式变更

### 5. 数据处理保障机制
- 实现数据匹配准确性验证机制，提供匹配成功率统计和异常值提示，确保数据补充的正确性
- 处理过程中自动创建原始文件和中间数据的备份，存储在应用指定的本地备份目录，防止原始数据丢失或损坏
- 采用事务处理机制，确保数据处理的原子性，任何步骤失败时自动回滚到初始状态

### 6. 前端与后端交互
- 开发直观的用户界面，包含文件选择区域（支持拖放功能）、数据特征选择面板、处理状态显示和结果预览区，布局清晰合理
- 实现前端到本地后端的高效异步通信（Electron IPC），确保文件解析和数据处理过程不阻塞用户操作，提供处理进度实时反馈
- 设计清晰的操作指引，包括步骤说明、功能提示和常见问题解答，帮助用户顺利完成操作

### 7. 结果预览功能
- 提供数据处理结果的表格预览界面，支持调整列宽和表格大小
- 支持预览数据的分页浏览（提供页码导航和每页条数选择）、多列排序和条件筛选功能
- 采用不同颜色或标记高亮显示已补充的数据，与原始数据明显区分，便于用户核对

### 8. 异常情况处理
- 文件格式错误检测与处理，提供明确的错误提示、格式要求说明和修复建议
- 数据特征不匹配检测，当检测到潜在的列名相似但不完全匹配时，提示用户可能的匹配选项或需要调整的内容
- 设置合理的文件大小限制（建议不低于100MB）和处理超时控制，防止系统过载，并提供明确的限制提示
- 本地处理错误处理，提供详细的错误信息和重试选项，支持断点续处理功能
- 全面的错误日志记录，存储在本地应用日志目录，包含时间戳、错误类型、堆栈信息等，便于问题排查和系统优化

应用整体应遵循直观易用的设计原则，确保普通用户能够在无需专业培训的情况下轻松完成文件上传、数据补充和结果下载的全过程，同时保证数据处理的准确性和本地数据安全性。

该应用为纯离线版，所有操作均在本地计算机完成，无需接入互联网，不进行任何数据上传，确保用户数据隐私安全。

### 技术栈要求
- 前端框架：React + Ant Design Pro
- 数据处理引擎：xlsx + csv-parser
- 文件验证 & 上传：file-type + progress
- 数据匹配逻辑：原生JS + lodash
- 备份 & 事务：fs-extra（Node.js文件操作）
- 打包成单文件：electron-builder

## 核心功能

### 1. 文件选择功能
- 支持选择两个数据文件（文件A和文件B）
- 支持格式：
  - CSV (.csv) - 逗号分隔值文件，UTF-8 编码
  - Excel (.xlsx) - Excel 2007+ 格式（Office Open XML）
  - Excel 97-2003 (.xls) - 旧版 Excel 格式（BIFF8）
- 支持原生文件对话框选择和拖拽上传
- 基于 file-type 库的严格文件类型验证（魔数检测）
- 文件大小限制（100MB）
- 数据量限制（最大 100,000 行，500 列）
- 实时显示解析进度和状态（准备中、解析中、完成、失败）

### 2. 数据匹配与补充功能
- 基于主键列匹配两个文件的数据
- 支持多列数据提取和补充
- 未匹配数据统一使用空值（NULL）填充所有选定列
- 直观的列选择界面
- 异常值检测：自动检测空值比例过高、匹配率过低、重复主键等问题

### 3. 结果生成功能
- 自动生成带原始文件名和时间戳的结果文件
- 支持 CSV 和 Excel 格式保存
- Excel 保存采用原位写入策略：仅修改目标列的 cell.v，保留非目标列及所有 cell.t / cell.z / 样式属性完全不变
- Excel 保存失败时自动降级为 CSV 格式，确保数据不丢失
- 自定义保存路径，保存后可直接打开所在文件夹

### 4. 数据处理保障
- **失败自动回滚**：任何步骤失败时自动回滚到初始状态
- **手动回滚**：支持随时手动回滚到原始状态
- **断点续处理**：处理中断后可从上次位置继续
- **暂停/恢复**：支持暂停处理并保存检查点，稍后恢复
- **自动备份**：处理前自动创建原始文件备份，备份与检查点统一归档到 backups 目录
- **备份自动清理**：超过 7 天的备份自动清理
- **处理超时控制**：默认 5 分钟超时保护
- 匹配成功率统计
- 保持原始数据顺序和结构

### 5. 结果预览功能
- 分页浏览、多列排序（按住 Shift 点击列头）、多列条件筛选
- 可拖拽调整列宽（react-resizable）
- 高亮显示已补充数据
- 匹配状态可视化

### 6. 日志系统
- 分级日志记录（DEBUG/INFO/WARN/ERROR），包含错误类型、名称和堆栈信息
- 日志持久化存储
- 日志轮转机制（单文件最大 10MB，最多保留 10 个文件）
- 自动清理过期日志（超过 30 天自动删除）

## 技术栈

- **前端框架**: React + Ant Design + Ant Design Pro Components
- **数据处理引擎**: xlsx + csv-parser（主进程流式解析）
- **文件验证**: file-type（基于魔数的严格文件类型检测）
- **进度反馈**: progress（主进程 I/O 进度）+ Ant Design Progress（UI 进度）
- **数据匹配逻辑**: 原生 JS + lodash
- **备份 & 事务**: fs-extra（Node.js 文件操作）
- **列宽调整**: react-resizable
- **桌面应用**: Electron（纯桌面端，无 Web 形态）
- **打包工具**: electron-builder
- **测试框架**: Jest + React Testing Library

## 数据安全

- 纯离线处理，无需网络连接
- 所有数据处理在本地完成
- 不上传任何用户数据
- 自动备份保护原始数据
- 失败自动回滚，支持手动回滚

### 架构说明

- **Electron 主进程** (`public/modules/`): 负责文件系统操作、数据处理、备份管理、结果保存、日志持久化
- **React 渲染进程** (`src/`): 负责 UI 展示和用户交互
- **共享匹配核心** (`matchCore.js`): 数据匹配算法抽取为独立模块，主进程（CommonJS）和渲染进程（ES Module）各一份，保持逻辑一致
- **预加载脚本** (`preload.js`): 安全地桥接主进程和渲染进程的 IPC 通信
- 大文件优化：主进程仅向渲染进程发送预览数据（最多 500 行），处理时从磁盘重新读取完整数据
